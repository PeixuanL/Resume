# 岗位搜索工具与 Skill 化计划

记录日期：2026-07-31

## 1. 定位

这个工具不是定时任务，也不是自动投递工具，而是一个 **手动唤起的岗位搜索与有效投递辅助流程**。

目标是把“看到一堆岗位链接”升级为：

```text
最新岗位发现 -> 对口筛选 -> JD 解码 -> 简历证据匹配 -> 投递动作包
```

每次运行都应该回答三个问题：

- 这个岗位是不是新的、还开放、值得看？
- 这个岗位和我的真实经历是否对口？
- 如果要投，应该用哪份简历、怎么改、怎么开口？

## 2. 硬边界

- 不做后台定时任务。
- 不主动运行，只有用户明确唤起时才搜索。
- 不登录或操作招聘平台账号。
- 不自动投递、不自动私信 HR。
- 不把规则、画像、搜索结果保存到仓库外的长期系统。
- 小红书、BOSS、脉脉等无法公开访问的内容，由用户提供截图、正文或链接后再结构化分析。
- 所有岗位判断必须基于可见 JD、公开信息、用户真实简历材料，不编造公司、薪资、规模、岗位职责或发布时间。

## 3. 目标产出

每次岗位搜索不追求数量，而追求可行动性。默认输出：

- Top 5-10 个可看岗位
- 每个岗位的来源链接与新鲜度判断
- 匹配理由与主要风险
- 投递建议：投 / 观望 / 放弃
- 推荐使用的简历版本
- 需要定向改写的 3 个点
- 高优先级岗位的轻量 JD 解码
- 可用于开场私信或投递备注的短话术

## 5. 搜索来源分级

P0：强验证来源

- 公司官网招聘页
- ATS 页面
- 官方公众号招聘
- 官方 LinkedIn / 人才页

P1：主要求职平台

- LinkedIn
- BOSS 直聘
- 猎聘
- 拉勾
- 脉脉

P2：线索来源

- 牛客
- 小红书
- 社群招聘帖
- 招聘合集
- 个人转发的 HR 信息

P3：弱来源

- 二手转载
- 无发布时间的聚合页
- 无法回源验证的截图

P2 / P3 只能作为线索，进入投递前必须尽量回到公司官网、官方招聘页或可验证 JD。

## 7. 筛选与评分

每个岗位按 5 个维度判断：

| 维度 | 判断问题 |
|---|---|
| 新鲜度 | 是否最近发布、仍在开放、来源可靠？ |
| 对口度 | 是否命中 AI、B 端、Agent、工业/楼宇/运维/SaaS 场景？ |
| 可投递度 | 年限、行业、城市、语言、薪资是否有合理空间？ |
| 转化率 | 是否能找到官网入口、HR、内推、明确投递渠道？ |
| 准备成本 | 是否需要大幅改简历或补齐大量行业知识？ |

默认保留：

- 高对口 + 新鲜 + 可投递
- 外企 / 海外协作 + AI / SaaS 强相关
- 虽然不是完全对口，但能用现有项目证据解释迁移能力

默认过滤：

- 纯销售、纯运营、纯算法研发
- 明显培训、外包、灰色招聘
- 要求资深 5-8 年以上且没有转化空间
- JD 过空、没有真实职责、无法验证来源

## 9. 与现有求职工作流的衔接

岗位搜索工具是 Offer Toolkit 的前置层：

```text
targeted-job-search
  -> 找到值得投的岗位
job-description-skill
  -> 解码 JD，判断该不该投
resume-skill
  -> 定向改简历
bq-skill
  -> 拿到面试后准备故事与追问
```

原则：

- 岗位搜索阶段只做轻量判断。
- 决定要投的岗位，再进入完整 JD 解码。
- 只有明确要投时，才做简历定向改写。
- 拿到面试后，再进入面试准备默认工作流。

## 10. Skill 化计划

暂定 skill 名：

- `targeted-job-search`
- 或 `job-search-skill`

触发方式：

- “帮我搜今天的 AI 产品岗”
- “帮我搜外企 B 端产品经理”
- “帮我看最近有没有数字孪生 / 智能楼宇方向”
- “我贴几条岗位，你帮我筛”
- “帮我把这些岗位按投递优先级排一下”

Skill 只负责：

- 读取仓库内候选人画像和事实源
- 生成搜索关键词
- 搜索或结构化用户提供的岗位
- 判断岗位是否值得投
- 生成岗位扫描报告
- 把高优先级岗位交给 JD 解码流程

Skill 不负责：

- 定时运行
- 自动登录平台
- 自动投递
- 自动私信
- 编造无法验证的信息
- 在仓库外保存长期求职数据

## 11. 分阶段推进

第一阶段：流程沉淀

- 建立候选人画像、关键词库、来源分级、评分标准、报告模板。
- 用 2-3 次真实岗位搜索测试这个流程。

第二阶段：模板稳定

- 固定岗位记录格式。
- 固定“投 / 观望 / 放弃”的判断口径。
- 固定轻量 JD 解码输出结构。

第三阶段：包装成本地 skill

- 将稳定流程写成 `targeted-job-search/SKILL.md`。
- 可选加入 `references/`：候选人画像、搜索关键词、评分标准。
- 可选加入 `scripts/`：生成报告骨架、去重、格式化岗位表。

第四阶段：与投递台账衔接

- 对已投、待投、放弃岗位建立状态记录。
- 每个强匹配岗位保留决策原因，避免重复纠结。

## 12. 下一步

先不创建 skill。下一步只做最小可用版本：

1. 创建岗位搜索记录目录。
2. 用一次真实搜索或用户提供的岗位截图跑通报告模板。
3. 根据结果再决定 `targeted-job-search` 的最终 skill 范围。
