# JD 拆解与匹配策略

## 面试官最可能判断的 6 件事

| 考点 | JD 信号 | 你的证据 |
|---|---|---|
| 复杂 B 端多角色平台 | 管委会端、企业端、服务商端 | Inspector 里拆一线人员、主管、专家、交付/售前等角色和告警-工单闭环 |
| AI 企服产品化 | AI 客服、企业参谋、政策匹配、合同/PPT/研报工具 | Inspector AI Agent / RAG 固定答案，可迁移到企业服务任务流 |
| 数据与地图/看板 | 产业大脑、数字孪生地图、产业链图谱、监管驾驶舱 | Designer / DFS 数据闭环、数字孪生、数据接入与看板能力 |
| 半定制落地 | 各地园区个性化定制、服务目录、准入规则 | 大客定制转标品、约 70% 定制需求转标品、实施周期压缩 |
| 政企/产业协同 | 管委会、服务商、产业研究团队 | 售前、POC、交付、客户成功与研发协同经验，需要承认政企园区经验是相邻迁移 |
| 结果与交付意识 | PRD、原型、业务规则、验收标准 | 50+ PRD/验收文档、Demo/POC、SOP、验收脚本和交付材料 |

## 你的主打法

优先讲：

1. **Inspector 设施运维 Agent**：证明能做 B 端复杂流程、AI 嵌入业务闭环、工单与知识沉淀。
2. **Designer / DFS 数据闭环**：证明数字孪生、数据接入、看板、空间/设备对象建模。
3. **定制转标品**：证明能处理多客户/多园区差异，把个性化需求沉淀成底座能力、配置项和实施基线。

不要主打：

1. 纯模型训练、算法调参、模型准确率。
2. 纯 3D 展示效果。
3. “我完全懂园区招商/惠企政策/供应链金融”。这些是需要补课的行业知识，应该说方法可迁移。

## 匹配话术

> 我看这个岗位的重点，不是做一个单点模块，而是围绕园区企业全生命周期，把管委会、企业和服务商三端的需求、资源、政策、数据和 AI 服务串起来。这个和我过去做设施运维 Agent 的方法是相通的：都要先把角色、业务对象、状态流、数据来源和人机边界拆清楚，再决定产品模块和交付范围。

> 我的直接经验不是经开区平台，但我做过 B 端复杂场景里的数字孪生、数据接入、告警/工单闭环、AI 辅助诊断、标品化和半定制交付。对园区平台来说，我会把经验迁移到企业画像、政策匹配、供需撮合、服务券核销、监管驾驶舱这些具体任务流里。

## 能力映射

### 园区三端平台

- 管委会端：监管驾驶舱、政策/补贴审核、招商线索、企业画像、产业链补链。
- 企业端：需求发布、政策匹配、服务券申领核销、合同/PPT/研报工具、供需资源对接。
- 服务商端：服务目录、准入规则、服务响应、履约评价、对账结算。

可用项目证据：

- Inspector：告警、资产、空间、知识、工单和人工确认多对象协同。
- 定制转标品：把不同客户组织流程和产品底座能力分层。

### 产业大脑 / 数据驾驶舱

你要把它讲成“指标和任务”，不要讲成“做大屏”：

- 产业结构：企业数量、营收、税收、产值、就业、研发投入、重点企业、链主企业。
- 招商：目标企业、产业链缺口、迁入可能性、上下游关系、联系人/线索状态。
- 企服：诉求量、服务响应时效、政策匹配率、申报进度、服务券核销、满意度。
- 风险：企业经营异常、政策过期、补贴异常、服务商履约异常、供应链金融风险。

可用项目证据：

- DFS 数据接入与分析画布。
- Designer / DFS 智能楼宇 Demo 中的设备点表、数据绑定、看板预警和端到端验收。

### AI 企服工具

迁移逻辑：

```text
设施运维 AI：告警 -> 上下文检索 -> 诊断建议 -> 工单草稿 -> 人工确认
园区企服 AI：企业诉求 -> 企业画像/政策/产业链检索 -> 匹配建议 -> 申报/方案草稿 -> 人工审核
```

可用固定答案：

- AI 不是聊天框，而是专业任务流。
- RAG 是上下文检索层，知识源要分层、引用、低置信兜底。
- AI 输出要有依据、置信度、缺失信息、下一步动作和人工确认。

## 风险与补救

| 风险 | 面试官可能问 | 回答策略 |
|---|---|---|
| 没有国家级经开区落地经验 | 你没做过园区平台，怎么胜任？ | 承认行业补课，但强调 B 端复杂流程、半定制、数据接入、AI 任务流经验可迁移 |
| 年限可能弱于 5-10 年 | 你经验深度够吗？ | 不硬碰年限，讲自己负责的完整链路和产出密度：PRD、原型、验收、POC、交付支持 |
| 供应链金融/政策细节不足 | 政策计算器/助贷怎么设计？ | 从产品方法讲：规则引擎、准入条件、材料清单、风控字段、人工审核、留痕 |
| AI 容易被追技术 | 你具体懂 RAG/Agent 到什么程度？ | 用固定答案讲产品侧输入输出、知识源、Schema、bad case 和验收，不说训练模型 |
