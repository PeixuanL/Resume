# 1.需求来源

## 1.1 来源产品规划

### 1.1.1 Inspector 8.1 工单闭环能力建设

为支撑设备监控场景下从告警触发、人工建单、标准 SOP 执行、现场维修、验收到闭环沉淀的完整链路，Inspector 8.1 需要新增和完善工单管理能力，并与运维助手端执行能力形成统一闭环。

## 1.2 来源项目

### 1.2.1 Inspector 8.1 运维闭环专项

当前系统已有部分工单页面原型，但在多设备、多步骤、流程图步骤、3D演示、运维助手执行、消息提醒、状态映射、模板引用边界等方面缺少统一设计，需要通过本次 PRD 进行统一收敛。

# 2.产品功能价值

1. 建立业务监控端到运维助手端的完整工单闭环，支撑从创建、下发、执行、验收到关闭的全流程。
2. 支持标准 SOP 引用与现场执行闭环，保证标准化能力可复用、执行经验可复盘。
3. 将 MR 能力限定为标准 SOP 的增强能力，避免临时工单直接耦合 MR 配置，降低复杂度。
4. 支持多设备工单按设备维度配置与执行，减少一线重复录入，提高工单创建与执行效率。
5. 让研发、测试、用户手册编写人员基于统一规则理解字段限制、状态变化、端侧差异和异常场景。

# 3.功能目标

- 功能目标1：实现业务监控端可独立完成工单创建、步骤配置、指派、流转、验收与关闭。
- 功能目标2：实现运维助手端可按 `待执行 / 执行中 / 已完成` 的执行视角查看并执行工单。
- 功能目标3：实现列表步骤和流程图步骤两种配置方式，并保证执行端闭环一致。
- 功能目标4：实现工单与模板库、告警、设备、MR、平台底座的接口解耦，支持模块即插即用。
- 功能目标5：保证消息提醒、异常标记、状态流转、字段约束规则清晰可测试。

# 4.名词解释

| 名词 | 解释 |
|---|---|
| 工单 | 业务监控端创建并下发，由运维助手端执行的维修/检查任务单据 |
| 业务监控端 | PC 端设备监控页面下的工单管理模块，负责工单创建、指派、管理、验收 |
| 运维助手端 | iOS 端工单执行模块，负责待办查看、步骤执行、3D演示、结果提交 |
| 模板库 | 标准 SOP 模板管理模块，本次 PRD 不展开详细功能，仅作为工单管理的依赖与约束说明 |
| SOP 模板 | 标准化步骤模板，可用于工单创建时引用；模板只绑定设备类型，不绑定设备实例 |
| 列表步骤 | 线性步骤配置方式，按顺序执行 |
| 流程图步骤 | 节点式步骤配置方式，支持判断节点分支执行 |
| 通用步骤 | 仅在多设备工单中开放的步骤，对工单内全部已选设备均生效，适用于安全确认、开工准备、收尾复核等共性动作 |
| 设备步骤 | 仅对某一台设备生效的步骤 |
| MR 剧本 | 标准 SOP 可绑定的一套完整 3D/MR 检查或维修方案；一个模板只允许绑定一个 MR 剧本 |
| 剧本范围 | 当前步骤或节点在模板绑定的 MR 剧本中的场景范围或章节片段 |
| 逾期 | 动态标记，不是工单状态；当当前时间晚于计划完成时间时标记为逾期 |
| 挂起 | 工单被暂时中止处理的主状态；挂起工单不进入运维助手主待办列表 |
| 驳回 | 验收动作，不是主状态；驳回后工单回到执行中 |
| 快照 | 工单创建时从模板、设备、MR 元数据等对象中复制出的运行时数据，后续不随源数据自动变化 |

# 5.客户场景描述

## 5.1 场景描述

客户在设备监控场景中，需要基于告警或人工发现的问题快速创建工单，明确责任人和计划时间，并按设备或位置配置检查/维修步骤。一线运维人员在运维助手端接收工单后，根据步骤或流程节点执行现场操作，必要时通过3D演示完成标准化检修。业务监控端最终对结果进行验收，并将可复用经验沉淀为标准模板。

## 5.2 客户业务流程

1. 业务监控人员在 PC 端查看工单列表和统计信息。
2. 业务监控人员新建工单，填写基础信息、选择设备或仅位置；单设备工单配置设备步骤，多设备工单配置通用步骤与设备步骤；仅位置工单本期仅支持先保存草稿，需在基础信息中补充设备后再配置步骤并下发。
3. 负责人在运维助手端查看待办工单，并在计划开始时间到达后进入执行。
4. 运维人员按步骤执行工单；若工单来源于带剧本的标准模板，则在满足条件的步骤中使用3D演示。
5. 运维人员提交执行结果后，工单进入待验收或直接关闭（取决于项目状态配置）。
6. 业务监控端进行验收，通过则关闭；驳回则返回执行中。
7. 已完成工单保留执行与验收记录，供后续经验复盘；本期不提供直接沉淀为模板的入口。

# 6.产品功能逻辑

1. 业务监控端提供工单管理能力，负责工单全生命周期管理。
2. 运维助手端仅提供工单执行能力，不承担模板管理或工单建模规则配置。
3. 模板库是工单的前置依赖能力，但非工单主流程前置条件；模板库关闭时，工单仍可手动创建和执行。
4. 工单创建时可手动编写步骤，也可按当前设备引用模板；模板引用采用发布版本快照，工单不直接读取模板草稿。
5. 工单执行时只消费工单私有步骤快照、设备快照和 MR 元数据快照，不依赖模板实时在线查询。
6. 告警、设备、MR、权限、附件、消息、日志等能力均通过标准接口与工单模块集成，不做页面级或库表级直连。

# 10.功能详细描述

## 10.1 查看工单列表（PC / 业务监控）

### 10.1.1 页面示意图

- 参考原型：`工单列表.png`
- 页面位置：设备监控页下工单管理列表首页
- 页面结构：顶部搜索筛选区 + 工单统计区 + 列表表格区 + 新建按钮

### 10.1.2 页面数据、操作及按钮说明

#### 10.1.2.1 操作说明

1. 具备工单管理权限的业务监控用户进入设备监控页后，点击左侧菜单中的工单管理入口，进入工单列表页。
2. 页面默认展示工单统计卡片、状态趋势图、未完成工单统计图和工单列表。
3. 用户可通过时间筛选、关键词搜索对工单列表进行过滤。
4. 点击列表行操作中的查看/编辑/删除图标，可进入对应详情或编辑操作。
5. 点击右上角【新建】按钮，打开“新建工单”右侧抽屉。
6. 点击列表行进入工单详情右侧抽屉，可根据工单当前真实状态显示不同的管理动作按钮。

### 10.1.3 页面涉及角色及权限说明

具备 `业务监控-工单管理-查看` 权限的用户可查看工单列表；具备 `业务监控-工单管理-创建` 权限的用户可看到【新建】按钮；具备 `业务监控-工单管理-编辑` 权限的用户可看到编辑类操作。

### 10.1.4 异常情况处理方案

1. 工单服务不可用时，页面显示“工单列表加载失败，请稍后重试”，保留筛选条件。
2. 统计图加载失败时，不影响列表展示，图表区显示占位和重试入口。
3. 当前用户无创建权限时隐藏【新建】按钮。

## 10.2 创建工单及基础信息（PC / 业务监控）

### 10.2.1 页面示意图

- 参考原型：`工单创建.png`、`工单创建_选择负责人.png`、`工单创建-选择设备.png`、`工单创建-选择设备-1.png`
- 页面位置：工单列表页点击【新建】后，从右侧打开“新建工单”抽屉
- 页面结构：页签区 + 基础信息区 + 检查步骤区 + 指派信息区 + 底部操作按钮

### 10.2.2 页面数据、操作及按钮说明

#### 10.2.2.1 操作说明

1. 点击工单列表页右上角【新建】按钮，打开“新建工单”抽屉。
2. 抽屉默认定位在 `工单信息` 页签，展示 `基础信息`、`检查步骤`、`指派信息` 三个区块。
3. 用户先填写基础信息，再在检查步骤区按设备配置步骤，最后在指派信息区选择负责人和计划时间。
4. 点击【保存为草稿】时，保存当前内容并生成一张 `待指派` 工单，不做下发，不要求负责人和计划时间必填。

#### 10.2.2.3 字段联动与限制规则

1. 工单创建页仅保留 `设备` 与 `位置` 两个字段，不新增显式的对象类型字段。
2. 未选择设备时，允许用户单独选择位置，用于“有故障区域但无明确设备”的场景。
3. 选择设备后，位置由设备位置快照自动带出且只读，不允许人工覆盖。
4. 若用户已手动选择位置后再选择设备，系统弹确认提示：“所选设备将自动带出设备位置并替换当前手选位置，是否继续？”
5. 用户确认后，当前位置被设备位置替换，且位置字段切换为只读；用户取消后，不添加该设备并保留原手选位置。
6. V1 不支持在同一张工单中自由拼接“不对应的设备 + 手工位置”；若设备跨多个位置，则基础信息仅展示精简位置摘要，明细在对象区查看。
7. 删除设备后，若位置仅来自该设备自动回填且无其他设备支撑，则位置同步清空；若仍有其他设备，则按剩余设备重新汇总位置摘要。
8. `来源=告警` 时，弹出“关联告警”模块，仅展示当前项目下未关闭告警。
9. 关联告警为可选单选；若选中告警，自动回填 `工单名称、描述、设备、位置、优先级`，用户仍可手动覆盖可编辑字段。
10. `来源=外接系统` 时，基础信息中的外接字段采用 `中文字段名（原字段名）` 展示方式。
11. `来源≠告警` 时，不展示关联告警模块。
12. 工单创建不提供“无检查步骤”模式；检查步骤必须在 `列表` 或 `流程图` 之间选择其一。
13. 工单创建支持 `通用步骤` 与 `设备步骤`；仅当工单选择了 2 台及以上设备时，才展示通用步骤区；单设备工单仅展示设备步骤区；仅位置工单不展示步骤配置区，需补充设备后再配置步骤。
14. 保存为草稿后工单真实状态为 `待指派`，并出现在业务监控端工单列表中。
15. `待指派` 工单可继续编辑、创建并下发、或删除；删除仅用于错误创建的未下发工单。
16. `故障提报 / 点巡检 / 预防性维护` 在本期仅作为来源预留值写入数据字典，不在前台下拉中展示，也不开放模块联动能力，待对应模块上线后启用。
17. 创建并下发时必须满足：
   - 基础信息必填项完整
   - 至少选择 1 台设备或 1 个位置
   - 至少存在 1 条步骤，且步骤配置合法
   - 已选择负责人
   - 已填写计划开始时间和计划完成时间
18. 草稿保存时可不校验负责人和计划时间，但基础信息至少需具备工单名称、设备或位置之一，以避免产生无意义空草稿。

#### 10.2.2.4 外接工单字段与步骤规则

1. `来源=外接系统` 时，基础信息中的外接字段需在中文业务字段后展示原始字段名，如 `工单名称（Tasks）`、`描述（Description）`。
2. 外接系统传入的检查步骤应在本系统内自动生成步骤快照，并标记为只读；业务监控端只能查看、不能编辑步骤结构。
3. 外接步骤若包含原系统字段、选项或状态码，本期不在前台单独展示字段映射，以原始系统 JSON 数据为准，供研发、测试和实施人员核对。
4. 只要工单已存在外接系统下发的步骤快照，则本系统禁止追加步骤、删除步骤、重排步骤、模板覆盖写入步骤，以及修改步骤结构、分支结构和记录项配置。
5. 外接工单在本系统内仅允许填写步骤结果、填写说明、上传附件、查看原始系统 JSON 数据与查看回填状态。
6. 工单执行完成后，需支持将步骤执行结果、文本说明、附件结果回填至原始系统；若回填失败，应保留回填失败标识并支持后续补偿。
7. 本期 PRD 只定义通用对接框架，不锁定 Forge 的具体字段映射表；Forge 详细映射将在后续《外接工单实施流程》文档中单独给出。

### 10.2.3 页面涉及角色及权限说明

具备 `业务监控-工单管理-创建` 权限的用户可创建工单；具备 `业务监控-工单管理-指派` 权限的用户可进行负责人选择与创建并下发。

### 10.2.4 异常情况处理方案

1. 未选择设备时，步骤区显示空态提示“仅位置工单暂不支持配置步骤，请先在基础信息中补充设备”；通用步骤入口不显示，设备步骤区和按设备选择模板入口隐藏或禁用。
2. 仅当工单选择了 2 台及以上设备时，才开放通用步骤区；单设备工单仅允许创建设备步骤；仅位置工单不允许创建任何步骤，也不允许创建并下发。
3. 仅位置工单如业务上确需补充设备，应通过“在基础信息中补充设备”的独立操作完成；转换为设备工单后，按所选设备重新生成步骤，并按规则处理原有未执行步骤。
4. 未配置任何步骤时，点击【创建并下发】提示“请至少配置一条步骤”。
5. 计划开始时间晚于计划完成时间时，禁止提交并提示时间关系错误。
6. 告警接口不可用时，仅隐藏或禁用关联告警能力，不影响手动建单主流程。
7. 模板库接口不可用时，仅禁用【选择模板】能力，不影响手动编写步骤。

#### 10.3.2.3 列表步骤限制规则

1. 工单列表步骤支持 `通用步骤` 和 `设备步骤` 两种作用范围；仅当工单选择了 2 台及以上设备时，才允许配置通用步骤。
2. 通用步骤对多设备工单内全部已选设备生效，适用于安全确认、开工准备、现场复核、工具归位等共性动作。
3. 设备步骤只对当前设备生效，不可跨设备复用执行结果。
4. 列表步骤结果类型固定为 `正常 / 异常 / 不适用`，不支持项目级自定义。
5. `必须记录项` 用于定义该步骤提交结果时统一需留存的记录项，对正常与异常结果共用。
6. 若步骤结果=`异常`，系统默认按 `文字说明或现场图片二选一必填` 校验；若步骤配置了 `必须记录项`，仍需继续满足。
7. 若步骤结果=`不适用`，系统要求填写 `不适用原因`。
8. 当前设备作用范围下可按该设备选择模板；模板导入后产生工单私有步骤快照。
9. 模板应用为设备级：为 A 设备应用模板不影响 B 设备，也不影响多设备通用步骤；未选择设备时不显示设备模板入口。
10. 本期不做扫码签到；P2 预留能力为“扫描设备码后直接拉起该设备对应的待办工单列表，并从列表进入执行”。

具备 `业务监控-工单管理-创建` 或 `业务监控-工单管理-编辑` 权限的用户可新增、编辑、删除列表步骤；模板引用能力还需模板库可用且用户具备模板查看权限。

### 10.3.4 异常情况处理方案

1. 当前设备未选中时，不允许调用当前设备模板。
2. 模板导入失败时，保留当前已录入步骤，不覆盖已有内容。
3. 删除步骤时若为最后一条步骤，删除后页面显示空态提示，不自动关闭步骤区。

#### 10.4.2.3 流程图限制规则

1. 一个流程图只服务于一个作用范围：要么是多设备通用步骤流程，要么是某台设备流程。
2. 不支持在同一张流程图中跨设备跳转。
3. 不支持并行节点、回环、子流程、3 个及以上分支。
4. 判断节点最多 2 个分支；若已创建第二分支，则第二分支的 `选项文案、条件说明、目标节点、分支性质` 必须同时填写完整。
5. 流程图必须形成从开始到结束的完整可达链路，否则不能创建并下发。
6. 流程图节点与列表步骤共用同一套业务字段，保证执行端展示一致。
7. 首版不提供“复制为列表步骤”能力。
8. 处理节点与列表步骤共用结果类型；判断节点不配置通用结果类型，只配置分支。
9. 判断节点默认支持 `不适用分支`；若进入 `异常分支`，则触发系统默认异常留痕规则：`文字说明或现场图片二选一必填`。
10. 处理节点结果=`异常` 时，系统额外强制 `文本说明` 必填；处理节点结果=`不适用` 时，系统要求填写 `不适用原因`。
11. 本期不做扫码签到；P2 预留能力为“扫描设备码后直接拉起该设备对应的待办工单列表，并从列表进入执行”。

### 10.4.3 页面涉及角色及权限说明

具备 `业务监控-工单管理-创建` 或 `业务监控-工单管理-编辑` 权限的用户可编辑流程图类步骤；模板引用能力需模板库可用且具备模板查看权限。

### 10.4.4 异常情况处理方案

1. 若存在未连通节点、未闭环流程、判断分支未配置完整，点击保存时提示具体缺失项并阻止提交。
2. 若用户尝试将含判断分支的流程图切回列表模式，提示“当前流程包含判断分支，暂不支持切换为列表模式”。
3. 节点删除后若导致流程断裂，系统需在画布中高亮未闭环位置并阻止下发。

## 10.6 工单流转与管理（PC / 业务监控）

### 10.6.1 页面示意图

- 参考原型：`工单详情_待执行.png`、`工单详情_待执行-重新指派.png`、`工单详情_维修员驳回后.png`
- 页面位置：工单详情右侧抽屉

### 10.6.2 页面数据、操作及按钮说明

#### 10.6.2.1 操作说明

1. 用户在工单列表点击工单，打开工单详情抽屉。
2. 详情页按真实状态展示不同信息和操作按钮。
3. 业务监控端可执行的管理动作包括：
   - 删除
   - 重新指派
   - 修改计划开始/完成时间（延期动作）
   - 挂起
   - 恢复
4. 删除仅适用于 `待指派` 工单：
   - 删除前需二次确认
   - 删除后工单从业务监控列表移除，且不进入运维助手端
5. `延期` 不是状态，而是修改计划时间的管理动作：
   - 允许修改计划开始时间和/或计划完成时间
   - 必须记录调整原因
   - 修改后工单仍保持原主状态
6. `逾期` 是动态标记：
   - 当前时间 > 计划完成时间，即标记逾期
   - 不改变主状态
7. `挂起` 为主状态，且仅适用于 `待执行 / 执行中`：
   - 挂起后工单不进入运维助手主列表
   - 恢复后仅回到挂起前的 `待执行` 或 `执行中`
8. 删除待指派工单时，若该工单存在关联告警，则需同步处理告警联动：
   - 删除前必须读取工单创建时保存的 `alarm_status_before_work_order_create`
   - 删除完成后解除工单与告警的关联关系
   - 将告警状态回滚到创建该工单前的原状态
   - 在告警详情页 `历史记录` Tab 中写入系统日志
9. 当工单来源为外接系统时，详情页不得修改来源系统下发的只读步骤结构；业务监控端仅可查看原始系统 JSON 数据、调整本系统可编辑字段和查看执行回填状态。

#### 10.6.2.2 数据及按钮说明

| 序号 | 字段名称 | 字段类型 | 数据来源 | 是否必填 | 字段描述 | 备注 |
|---|---|---|---|---|---|---|
| 1 | 基础信息 | 展示区 | 工单基础信息快照 | / | 展示名称、编号、类型、来源、优先级、描述、设备、位置等 | 详情页只读 |
| 2 | 检查步骤 | 展示区 | 工单步骤快照 | / | 若工单存在多设备通用步骤，则按通用步骤、设备步骤展示步骤摘要，并显式展示参考资料与必须记录项 | 只展示，不展示模板映射关系 |

| 4 | 执行记录 | 展示区 | 运维助手执行结果 | / | 展示执行结果、设备状态、现场图片/视频、说明 | 待验收及已关闭时重点展示 |
| 5 | 工单操作日志 | 展示区/页签 | 工单日志 | / | 展示工单创建、指派、执行、验收、驳回等操作日志 | 原“历史信息”页签统一命名 |

| 7 | 验收记录 | 展示区 | 验收记录 | / | 展示验收人、时间、结果、意见、驳回原因 | 已验收后展示 |
| 8 | 删除 | 按钮 | / | / | 删除错误创建的待指派工单 | 仅待指派可见，需二次确认；若有关联告警需触发告警回滚与历史留痕 |
| 9 | 重新指派 | 按钮 | / | / | 修改负责人 | 待执行、执行中、待验收可见 |
| 10 | 调整计划时间 | 按钮 | / | / | 修改计划时间并记录原因 | 替代延期状态 |
| 11 | 挂起 | 按钮 | / | / | 将工单状态置为挂起 | 仅待执行、执行中可见 |
| 12 | 恢复 | 按钮 | / | / | 将挂起工单恢复到挂起前状态 | 仅挂起时可见，且仅恢复到待执行或执行中 |
| 13 | 告警原始状态快照 | 隐式字段 | 告警模块 | 来源=告警且已关联时必填 | 保存创建该工单前的告警状态 | 用于删除待指派工单时回滚告警状态 |

#### 10.6.2.3 流转规则

1. 主状态固定为 `待指派 / 待执行 / 执行中 / 待验收 / 已关闭 / 挂起`。
2. 删除不是状态动作；仅 `待指派` 工单可删除，且删除后不可恢复。
3. 驳回不是主状态；待验收工单被驳回后回到 `执行中`。
4. 运维助手端的 `已完成` 分组包含 `待验收 + 已关闭`，但业务监控端详情页始终展示真实状态。
5. 未到计划开始时间的待执行工单，不出现在运维助手待执行列表。
6. 逾期标记可出现在 `待执行` 和 `执行中`。
7. 当 `来源=告警` 且工单已关联具体告警时，删除待指派工单后，告警状态必须回滚为创建该工单前的原状态；原状态至少支持 `未响应`、`已确认`。
8. 删除待指派工单的联动执行顺序固定为：
   - 校验工单状态=`待指派`
   - 校验是否存在关联告警
   - 若存在关联告警，则读取 `alarm_status_before_work_order_create`
   - 删除工单
   - 解除工单-告警关联
   - 回滚告警状态
   - 写入告警历史记录
9. 若删除联动中任一关键步骤失败，删除操作整体失败或进入事务回滚，不允许出现“工单已删除但告警未恢复”的不一致状态。

### 10.6.3 页面涉及角色及权限说明

具备 `业务监控-工单管理-管理` 权限的用户可进行重新指派、调整计划时间、挂起、恢复等管理操作。

### 10.6.4 异常情况处理方案

1. 非待指派工单不显示删除入口；若接口层收到非法删除请求，应返回“当前状态不允许删除”。
2. 当工单存在关联告警但缺少 `alarm_status_before_work_order_create` 快照时，删除操作应失败，并提示“缺少告警状态快照，无法安全删除关联工单”。
3. 删除待指派工单成功后，系统必须在告警详情页 `历史记录` Tab 中新增系统日志，日志文案至少包含：操作时间、操作人、被删除工单号、状态回滚结果。
4. 被删除工单号在告警历史中必须保留纯文本展示，即使工单详情页已不可跳转也不得丢失该文案。
5. `待指派 / 待验收 / 已关闭` 工单禁止执行挂起；已关闭工单也禁止恢复、重指派等动作。
6. 调整计划时间时若完成时间早于开始时间，禁止提交。
7. 挂起后若运维助手端仍持有本地缓存，执行端应在下次刷新或同步时移出主待办列表。

#### 10.8.2.3 工单详情页规则

1. 运维助手端保留独立工单详情页，作为待办列表和执行页之间的中间页。
2. 详情页展示内容包括：
   - 工单基础信息（含来源）
   - 设备信息与位置信息
   - 计划开始时间、计划完成时间
   - 已逾期、已驳回等状态标记
   - 驳回原因（有则展示）
   - 外部系统只读同步提示（来源=外接系统且步骤结构只读时展示）
   - 步骤摘要
   - 是否存在 3D演示 可执行步骤
3. 详情页主按钮按真实状态映射：
   - `待执行`：显示【开始执行】
   - `执行中`：显示【继续执行】
   - `待验收 / 已关闭`：显示【查看结果】或只读状态按钮
4. 详情页不承担复杂执行录入，仅作为进入执行页前的信息确认页。

### 10.8.3 页面涉及角色及权限说明

具备 `运维助手-工单执行-查看` 权限的用户可查看待办工单列表并进入工单详情页；具备 `运维助手-工单执行-执行` 权限的用户可从详情页进入执行页。

### 10.8.4 异常情况处理方案

1. 未到计划开始时间的待执行工单不在运维助手主列表展示。
2. 若工单变为挂起，下次刷新后从主列表移除。
3. 工单详情查询失败时，展示错误提示并允许返回列表。
4. 列表接口异常时展示空态和重试按钮，不自动跳转。

## 10.9 按步骤执行工单（iOS / 运维助手）

### 10.9.1 页面示意图

- 参考原型：`check.png`、`check-1.png`、`workorder-ipad横.png`
- 页面位置：运维助手待办列表点击工单后先进入详情页，再从详情页进入执行页

### 10.9.2 页面数据、操作及按钮说明

#### 10.9.2.1 操作说明

1. 用户点击工单卡片进入执行页后，页面顶部展示工单执行进度。
2. 执行页仅展示执行相关信息，不展示模板、SOP 映射关系等后台概念。
3. 工单执行顺序按步骤快照决定；若工单已配置多设备通用步骤，则先执行通用步骤，再执行各设备步骤。
4. 多设备工单顶部展示设备切换栏；单设备工单不显示设备切换栏。
5. 列表类步骤执行时，按顺序逐条展示步骤卡片。
6. 流程图类步骤执行时，展示当前节点卡片；若当前节点为判断节点，则展示分支按钮。
7. 用户可在执行页打开设备资产详情抽屉，查看当前设备资产档案、属性、图片及关联信息。
8. 用户可从设备资产详情抽屉进入整个空间场景的 3D 漫游模式。
9. 当步骤存在关联MR剧本时，用户点击【3D演示】先进入纯 3D 剧本播放页；若终端支持 MR，可在剧本页内进一步进入 MR 模式。
10. 3D 场景与剧本场景生命周期规则如下：
   - 打开剧本前关闭当前漫游场景实例
   - 剧本播放中若切换到下一剧本，需先关闭当前剧本实例
   - 退出工单、退出剧本或切换到其他工单时，关闭当前剧本实例
   - 从剧本返回执行页时，恢复到执行页对应步骤位置；不自动恢复已关闭的剧本实例
11. 执行完成后，用户点击【提交完成】提交工单。
12. 提交后：
   - 若项目启用待验收状态，则工单进入 `待验收`
   - 若项目未启用待验收，则工单直接进入 `已关闭`
   - 在运维助手端，以上两种情况都进入 `已完成` Tab

#### 10.9.2.3 列表步骤执行规则

1. 列表步骤按顺序执行。
2. 若当前步骤为必做，未选择结果前不可点击【完成本步】。
3. 若步骤配置了 `必须记录项`，则结果为正常或异常时，对应记录项都必须补齐后才能完成当前步骤。
4. 若选择 `异常`，除满足步骤配置的 `必须记录项` 外，系统默认还要求 `文字说明或现场图片二选一必填`。
5. 若选择 `不适用`，必须填写不适用原因。

#### 10.9.2.4 流程图步骤执行规则

1. 执行页只展示当前节点，不展示完整流程建模图。
2. 当前节点为处理节点时，表现形式与列表步骤一致，并使用 `正常 / 异常 / 不适用` 结果类型。
3. 当前节点为判断节点时，页面底部展示最多 2 个分支按钮，不再显示通用结果类型。
4. 分支按钮文案直接使用创建端配置的 `分支选项文案`。
5. 用户点击某个分支按钮后，流转到该分支的目标节点；若该分支被标记为 `异常分支`，则触发系统默认异常留痕规则：`文字说明或现场图片二选一必填`；若分支被标记为 `不适用分支`，则要求填写不适用原因。
6. 运维助手执行端不支持自由跳节点，只允许按当前节点允许到达的分支前进。
7. 不允许跨设备跳转；若某节点不属于当前设备，不应在当前设备执行流中出现。

#### 10.9.2.5 执行限制与对象直达规则

1. 运维助手主路径固定为 `待办列表 -> 工单详情 -> 执行页`。
2. 外接工单若由外部系统下发了检查步骤，则本系统执行页中的步骤结构只读，不允许修改步骤名称、顺序、分支结构和记录项配置；执行人员仅可补充结果、说明和附件。
3. 外接工单执行页不得新增步骤、删除步骤、重排步骤，也不得引用模板覆盖现有外接步骤结构。
4. 流程图执行时，只允许点击当前节点可到达的分支按钮；不支持跨节点、跨设备自由跳转。
5. 本期不做扫码签到；P2 预留能力为“扫描设备码后直接拉起该设备的待办工单列表，并从列表进入执行”。

### 10.9.3 页面涉及角色及权限说明

具备 `运维助手-工单执行-执行` 权限的用户可进入工单执行页并提交步骤结果。

### 10.9.4 异常情况处理方案

1. 必做步骤未完成时，禁止整单提交。
2. 流程图判断节点分支缺失时，工单不应允许下发到执行端；若异常进入执行端，应提示“流程配置异常，请联系管理员”。
3. 当前工单被业务监控端驳回后，执行页顶部显示驳回原因，并定位到需补做步骤。
4. 当前工单被挂起后，下次进入执行页需提示工单已挂起并退出执行。

## 10.10 3D演示（iOS / 运维助手）

### 10.10.1 页面示意图

- 参考原型：`check-1.png`、`workorder-ipad横.png`
- 页面位置：运维助手工单执行页中的步骤内入口

### 10.10.2 页面数据、操作及按钮说明

#### 10.10.2.1 操作说明

1. `3D演示` 不是工单级统一入口，只在满足条件的步骤中显示入口。
2. `3D演示` 入口显示条件必须同时满足：
   - 项目启用剧本/MR能力
   - 当前步骤继承了有效的 `script_id`
   - 当前步骤存在有效 `script_scope`
   - 当前终端至少支持纯 3D 剧本播放；若支持 MR，则可在剧本页内再进入 MR 模式
1. 用户点击【3D演示】后，先进入纯 3D 剧本播放页，不直接进入 MR 模式。
2. 纯 3D 剧本页内，可进一步点击【进入MR模式】切换到 MR 模式。
3. 退出 MR 模式时，先返回纯 3D 剧本页；退出剧本后再返回工单执行页。
4. 3D演示仅作为步骤执行辅助能力，不改变工单状态机。

#### 10.10.2.2 数据及按钮说明

| 序号  | 字段名称   | 字段类型 | 数据来源         | 是否必填 | 字段描述              | 备注           |

#### 10.10.2.3 MR 约束规则

1. 工单不直接配置剧本，只有引用带剧本的标准模板时，工单步骤才继承剧本元数据。
2. 一个 SOP 模板只允许绑定一个3D演示剧本。
3. 模板未绑定剧本时，对应工单步骤不显示3D演示入口。
4. 若 MR 平台不可用但纯 3D 剧本能力可用，则仍允许进入剧本播放页，仅隐藏【进入MR模式】。
5. 若剧本资源不可用，则仅隐藏或禁用3D演示入口，不阻断普通步骤执行。

### 10.10.3 页面涉及角色及权限说明

具备 `运维助手-工单执行-执行` 权限且项目启用剧本/MR能力的用户，可在满足条件的步骤中使用3D演示。

### 10.10.4 异常情况处理方案

1. 3D演示资源不存在或加载失败时，提示“3D演示资源暂不可用，请按普通步骤继续执行”。
2. 终端不支持 MR 但支持纯 3D 剧本播放时，仅进入剧本播放页，不显示【进入MR模式】。
3. 终端既不支持纯 3D 剧本也不支持 MR 时，隐藏3D演示入口。

#### 10.11.2.1 操作说明

7. 产品内消息默认只发送给仍需继续处理该事件的相关角色，不向操作发起人本人重复发送其已完成的操作结果；仅留痕事件不进入消息列表，只写入历史记录/操作日志。

以下消息类型均指**产品内消息面板/抽屉**中的消息范围；iOS 系统通知仅覆盖 10.11.5 所述的关键告警提醒。

1. 工单已创建并下发给负责人（接收：被指派负责人；创建人不重复接收）
2. 工单被重新指派（接收：新负责人、原负责人；变更发起人不重复接收）
3. 工单进入待验收（接收：验收人、当前执行负责人）
4. 工单被驳回（接收：执行人、当前负责人）
5. 工单计划时间被调整（接收：当前负责人、验收相关人）

以下事件仅作为留痕，不进入产品内消息面板/抽屉、未读角标或 iOS 系统通知：

1. 工单已验收关闭
2. 告警已生成关联工单
3. 关联工单草稿被删除并导致告警状态回滚
4. 与工单联动相关的告警确认或状态调整

### 10.11.3 页面涉及角色及权限说明

具备相应端侧工单或告警权限的用户，可看到与自己相关的系统消息；无对应业务权限的用户不展示相应消息内容。

### 10.11.4 异常情况处理方案

1. 顶部消息面板不可用时，不影响工单和告警主流程，仅不展示未读角标和消息列表。
2. 消息跳转目标已不存在或无权限时，提示“目标对象不存在或已无权限访问”，并退回对应列表页，消息保持未读状态。

### 10.11.5 iOS 系统推送通知

#### 10.11.5.1 页面示意图

- 参考原型：iOS 系统通知栏、锁屏通知样式
- 页面位置：iOS 手机系统层通知

#### 10.11.5.2 页面数据、操作及按钮说明

##### 10.11.5.2.1 操作说明

1. iOS 系统推送仅用于告警类关键提醒，不承载产品内完整消息列表能力。
2. 系统推送仅覆盖业务上最需要立即关注的告警事件，主要包括：
   - 新增告警
3. 不推送以下变化：
   - 告警关联工单
   - 删除关联工单后的状态回退
   - 告警确认或已确认类状态变化
   - 工单链路的中间态变化
4. 用户点击系统通知后，按对象直达告警详情页；若对象不可达，则退回告警列表页并保持对应产品内消息未读。
5. 仅当用户成功进入目标对象页后，对应产品内消息才自动标记为已读。

##### 10.11.5.2.2 数据及按钮说明

| 序号 | 字段名称 | 字段类型 | 数据来源 | 是否必填 | 字段描述 | 备注 |
|---|---|---|---|---|---|---|
| 1 | 通知标题 | 文本 | 平台通知能力 | 是 | 告警提醒标题 | 如“新增告警” |
| 2 | 告警编号 | 文本 | 平台通知能力 | 是 | 当前告警唯一编号 | 用于识别对象 |
| 3 | 状态摘要 | 文本 | 平台通知能力 | 是 | 告警状态简述 | 如“待处理” |
| 4 | 触发时间 | 文本 | 平台通知能力 | 是 | 通知产生时间 | |
| 5 | 点击跳转 | 交互 | / | / | 跳转到告警详情页 | 按对象直达 |
| 6 | 未读状态同步 | 隐式规则 | 平台通知能力 | 否 | 成功进入目标页后同步产品内消息已读状态 | 系统通知本身不承担归档 |

#### 10.11.5.3 页面涉及角色及权限说明

具备相应告警查看权限且安装 Inspector iOS 客户端的用户，可接收 iOS 系统推送通知。

#### 10.11.5.4 异常情况处理方案

1. 系统推送通道不可用时，不影响产品内消息面板展示。
2. 通知点击目标不存在或无权限时，退回告警列表页并保持未读。
3. 若用户关闭 iOS 系统通知权限，仅影响系统推送，不影响产品内消息入口。

# 11.对其他产品的影响

## 11.1 模板库

### 11.1.1 影响内容

工单创建时可按当前设备引用模板，因此模板库需提供发布版本查询、模板详情等接口能力；本期不要求提供工单反向沉淀入口。

### 11.1.2 需配合调整事项

1. 模板需按设备类型管理，不绑定设备实例。
2. 模板需区分草稿与发布版本。
3. 模板需支持一个模板绑定一个 MR 剧本。

## 11.2 告警模块

### 11.2.1 影响内容

工单创建时支持来源为告警，并可单选关联未关闭告警。

### 11.2.2 需配合调整事项

1. 提供未关闭告警列表和详情查询接口。
2. 提供工单-告警关联关系回写能力。
3. 告警状态机不得与工单状态机共享字段或强绑定。
4. 当来源=告警的待指派工单被删除时，告警模块需支持按工单创建前保存的状态快照回滚告警状态。
5. 告警详情页 `历史记录` Tab 需支持写入系统日志，记录删除关联工单草稿及状态回滚行为。
6. 告警历史日志中必须保留被删除工单号的纯文本展示，即使该工单已不可跳转。

## 11.3 设备模块

### 11.3.1 影响内容

工单创建可选择设备实例，也可仅选择位置；执行中对已选设备使用设备快照；仅位置工单本期不支持配置步骤，需在基础信息中补充设备后转换为设备工单；单设备工单展示设备步骤，多设备工单展示通用步骤与设备步骤。

### 11.3.2 需配合调整事项

1. 提供设备实例列表和设备类型接口。
2. 工单创建后，设备名称、位置、类型需快照化。
3. 设备主数据变化不应反向污染历史工单。

## 11.4 MR 平台

### 11.4.1 影响内容

工单执行在标准 SOP 场景下需要加载 MR 剧本资源。

### 11.4.2 需配合调整事项

1. 提供剧本列表、剧本元数据、剧本资源加载能力。
2. 工单执行仅消费 `script_id + script_scope` 快照，不依赖模板库实时查询。
3. MR 不可用时需要具备降级策略。

## 11.5 产品内消息入口

### 11.5.1 影响内容

工单创建、指派/重指派、驳回、待验收、计划时间调整等需要继续处理的动作型事件，需要通过顶部轻量消息面板/抽屉提醒相关人；工单已验收关闭以及告警关联、回滚、确认等仅留痕事件不进入消息通知。iOS 系统推送通知仅承载关键告警提醒，不承担完整消息归档。

### 11.5.2 需配合调整事项

1. 支持顶部消息入口未读角标。
2. 支持在顶部轻量消息面板/抽屉中统一展示工单消息和告警消息。
3. 支持按端侧跳转到工单详情/执行页或告警详情。
4. 若对象不可达，需退回对应列表并提示。

## 11.6 平台底座

### 11.6.1 影响内容

工单管理模块依赖平台统一的权限、项目、附件、通知、日志、字典等能力。

### 11.6.2 需配合调整事项

1. 提供模块开关和权限码控制能力。
2. 提供统一附件上传下载。
3. 提供项目上下文、审计日志和统一字典。

## 11.7 外接系统

### 11.7.1 影响内容

工单管理模块需支持对接外接工单系统，按外部字段映射生成本系统工单，并支持步骤只读展示、执行结果回填和失败补偿。

### 11.7.2 需配合调整事项

1. 提供原系统字段到 Inspector 字段的映射规则，并支持在界面中显示“中文字段名（原字段名）”。
2. 提供外接步骤结构映射、步骤只读快照生成能力，以及执行结果、附件、说明回填能力。
3. 提供回填失败后的补偿、重试和对账机制。
4. 后续需单独输出《外接工单实施流程》文档，覆盖字段映射、状态映射、联调、验收和上线切换。

# 13.升级问题

1. 业务监控端工单页面将以现有设备监控页下工单相关 Frame 为基础做增量升级，不重做整体导航结构。
2. 新建工单、工单详情仍使用右侧抽屉形态，以保证与现有原型风格一致。
3. 运维助手端工单列表将统一按 `待执行 / 执行中 / 已完成` 分组展示，需要替换旧的按真实状态直出方式。
4. 原有“延期”状态若存在历史实现，需要调整为“计划时间调整动作 + 逾期动态标记”模型。
5. 原有“无检查步骤”概念在本期不保留，统一收敛为列表模式或流程图模式。
6. 原有工单执行页面若直接展示模板/SOP 等后台概念，需要在本期删除，仅保留一线执行所需信息。
