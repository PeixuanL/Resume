# 面试准备默认工作流

来源任务：`019fa769-635c-75e3-abe6-0c2db0de8b0d` 最后一轮。

以后准备面试时，默认按这套方式来：这不是单次润色答案，而是一个 `JD × 简历/故事库 × 面试轮次 × 真实面经检索` 的准备流水线。

## 核心原则

- 不从“能力关键词”直接生成答案，要从“真实事件碎片”生成故事。
- 简历、故事库、用户补充里没有的信息，不能写成事实。
- 缺少动作、数字、背景、冲突、结果时，先追问或标成 `【待补充】`。
- 答案要口语自然，像真实经历过的人讲现场，不像背 STAR 模板。
- 优先呈现具体场景、人物、限制、动作、权衡、结果变化和复盘。

## 标准流程

1. JD 解码

提取 Must-have、Nice-to-have、Hidden signals、岗位 level、真实招聘意图、淘汰风险点。不要一上来出题。

同时把 JD 拆成可检索的方向标签。常用标签：

- AI 产品化 / Agent 任务闭环
- 复杂 B 端业务拆解
- 项目需求转标品 / 产品沉淀
- 方案 / 售前 / GTM 协同
- 跨团队推进 / 研发协作
- 验证与验收意识
- 行业学习与迁移能力
- 英文 / 海外 / 跨文化表达

2. 简历与故事库映射

先查已有简历、项目材料、故事库和面试沉淀，给经历打能力标签：

- ownership
- 复杂问题解决
- 跨团队影响力
- 模糊环境推进
- 冲突处理
- 失败与复盘
- 结果交付
- JD 缺口

3. 题库检索与拼装

每次准备面试时，不要只重写一篇答案。先按 JD 标签和面试轮次，从通用题库里抓素材，再按岗位重点拼装。

题库入口优先级：

1. `03_面试准备/00_通用答案库/通用面试题库_当前确认版.md`：当前重新确认后的主题库入口。后续答案优先从这里抓。
2. `03_面试准备/02_通用面试工具与规范/自我介绍与项目经历文稿_确认工作稿_2026-08-03.md`：自我介绍模块拼装规则和能力模块库。确认后再迁移到当前题库。
3. `03_面试准备/00_通用答案库/自我介绍与项目经历定稿_2026-08-01.md`：较稳定的自我介绍、项目定义、结果证据卡和临场压缩规则，可作为当前题库的事实来源。
4. `03_面试准备/00_通用答案库/面试问答沉淀.md`：历史通用题库，只作为资料源和旧素材参考，不直接当当前定稿复用。
5. `03_面试准备/00_通用答案库/AI产品经理可复用答案库_真实项目深挖版.md`：AI Agent、RAG、准确性、研发调优、交付边界等深挖素材，只作为专项资料源，迁移前要重新确认表达。
6. `03_面试准备/00_通用答案库/AI产品全流程补强与面试口径.md`：AI 产品流程、Prompt/RAG/Agent/Schema/验收/bad case 的结构化口径，只作为专项资料源。
7. `03_面试准备/00_通用答案库/B端AI产品经理-面试追问清单.md`：高压追问、防守边界和风险题，只作为资料源。
8. 目标公司/岗位文件夹里的 `final-answers.md`、`saved-edits.md`、复盘、二面准备和已确认答案。

旧素材隔离规则：

- `面试问答沉淀.md`、历史公司面试包、旧 HTML/webapp 里的答案，都属于资料源，不属于当前确认版题库。
- 可以从旧素材里抓事实、项目片段、面试官追问、风险点和表达灵感。
- 不能直接复制旧答案作为新答案；必须重新确认事实边界、岗位落点、口语表达和是否存在 AI 味。
- 只有迁移进 `通用面试题库_当前确认版.md` 的内容，才算当前题库里的可复用答案。

按题型抓素材：

| 题型 | 先抓什么 | 拼装规则 |
|---|---|---|
| 自我介绍 | 万能开头 + JD 标签对应 3 个能力模块 | 控制 60 秒；只放 3 个模块；不堆项目细节 |
| 项目介绍 / 项目深挖 | Inspector / Designer / 售前 POC 等项目故事 | 先选最贴 JD 的项目，再补 1 个备用项目 |
| AI 产品理解 | AI Agent / RAG / 输出结构 / 人审 / bad case | 先讲业务流程，再讲机制，不先堆技术词 |
| 个人贡献 | 事实边界、负责模块、参与/协同边界 | 讲清“我负责什么、团队做什么、我怎么推动” |
| MVP / 优先级 | 项目需求转标品、核心业务闭环、客户验证 | 讲取舍标准和例子，不写成抽象方法论 |
| 验证 / 指标 | Demo、POC、场景脚本、验收 case、客户/交付反馈 | 交付阶段信号和后续运营指标分开说 |
| 研发/跨团队协作 | PRD、字段、状态、原型、验收、bad case | 把“沟通能力”落到产研协作产物 |
| 方案 / 售前 / GTM | 方案、演示、培训、市场文案、交付边界 | 讲客户价值和边界对齐，不说自己独立签约 |
| 行业迁移 | 用户任务、业务流程、关键数据、专家规则、验收标准 | 先拆新行业，再迁移旧方法 |
| 英文 / 海外 | UCL、海外客户、英文资料、海外用户表达 | 减少设施运维术语，讲任务、路径、价值 |
| 行为题 / 失败复盘 | 冲突、压力、失误、复盘素材 | 只用真实事件；缺细节先追问 |

按岗位拼装默认组合：

| JD 方向 | 默认抓取组合 |
|---|---|
| 通用 B 端产品 | 复杂 B 端业务拆解 + 项目需求转标品 + 跨团队推进 / 验证与验收 |
| AI 产品 / Agent | AI 产品化 / Agent 任务闭环 + 复杂 B 端业务拆解 + 验证与验收 |
| 解决方案 / GTM | 方案 / 售前 / GTM 协同 + 项目需求转标品 + 客户/交付边界 |
| 跨行业 / 新行业 | 行业学习与迁移能力 + 复杂 B 端业务拆解 + 验证与验收 |
| 海外 / 英文协作 | 英文 / 海外表达 + AI 产品化或复杂 B 端业务拆解 + 方案 / GTM 协同 |

输出答案时，必须标明素材来源和事实边界。如果素材库里没有足够证据，不要硬写，先问用户，或标 `【待补充】`。

4. 真实面经检索

当公司、岗位或轮次明确时，结合公开资料检索真实面试经验。问题来源要区分：

- 官方招聘说明
- Glassdoor / Reddit / Blind / 牛客 / 脉脉等面经
- 通用行业经验

每条参考标注可信度：高 / 中 / 低。

5. 生成问题

默认生成 Top 20 可能问题，并按轮次和面试官角色分组：

- HR / Recruiter：动机、稳定性、匹配度、薪资、沟通表达
- 业务一面 / Peer：是否真的做过、能否落地、项目细节
- Hiring Manager：level、判断力、ownership、优先级和权衡
- Cross-functional：协作、冲突、影响力、边界推进
- Final / 管理层：上限、价值观、失败复盘、长期潜力

每个问题必须包含：英文问题、中文解释、面试官真正想考什么、为什么这一轮会问、对应 JD 条目、推荐使用哪个真实经历、缺口或风险追问。

6. 生成答案

只为 Top 5 必练问题生成完整答案。每个答案默认输出：

- 60 秒中文口语版
- 2 分钟中文详细版
- 英文面试版
- 面试官可能追问
- 我需要补充确认的细节

## 答案质量标准

好答案应该能看到：

- 证据来源：简历、故事库、项目材料、用户补充
- JD 命中：对应能力或 hidden signal
- 面经命中：来自哪类真实面试经验
- 可信度：高 / 中 / 低
- 素材完整度：完整 / 需要补充

禁止输出：

- 只有抽象能力，没有具体事件
- 只有“我们做了”，没有“我做了”
- 只有结果，没有过程和权衡
- 只有专业名词，没有真实场景
- 编造简历里没有的数字、客户、项目规模、职位职责
- 过度完美，没有困难、限制或反思

## 如果用户只给一个问题

先查已有故事能否匹配；如果素材不足，一次只问一个关键追问。优先追问：

- 当时具体发生了什么？
- 为什么这个问题麻烦？
- 谁和谁有分歧，谁在等结果？
- 你个人做的第一件事是什么？
- 中间有什么权衡？
- 最后状态发生了什么变化？

然后再生成自然口语答案。
